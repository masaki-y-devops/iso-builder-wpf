## 概要

ファイル・フォルダ（複数可）をドラッグアンドドロップすると、``Backup_(きょうの日付).zip``に圧縮して、

それをそっくりそのまま``Backup_(きょうの日付).iso``としてデスクトップに出力するアプリをつくってみた。

AI(Gemini)支援を利用して作成。**実装→問題点発生→質問して潰す** 、を比較的高速で回すことができた。

## なぜ作ったか

ファイルバックアップのために、内蔵HDD、USB HDDに加え、

**書き換え不能の特性が長所な光学ディスク(BD-R,一部M-DISC)をまとめ買いして使用**している。

従前、[ImgBurn](https://portableapps.com/apps/music_video/imgburn-portable)や[BurnAware](https://burnaware.com/)で手動でISOを作成していたが、

ディレクトリ階層が深くなると、ISO作成自体は可能なもののディスクに焼くときにエラーが多発、何枚も空のディスクを無駄にしてしまっていた。

なので仕方なく、**手動でZIPにまとめてISO化、を行っていたが、これが非常に面倒。**

出力先はデスクトップでいいから、**D&Dしたらワンストップでこれらの定型作業をこなしてくれて、自分は空のディスクを用意して焼くだけでOK、な一部自動化を実現** した。

## 使い方

x86-64専用です。

.NET 10ランタイムが必要です。ダウンロードはこちら → [Microsoft公式](https://aka.ms/dotnet/10.0/windowsdesktop-runtime-win-x64.exe)

1. Releaseページよりダウンロード後、任意のディレクトリで起動してください。

2. 起動したら、処理したいファイル・フォルダを一度にドンとドラッグアンドドロップしてください。

→ 進捗バーが稼働し、そのファイル・フォルダ構造のまま、``Backup_YYYYmmdd.zip``がデスクトップ上に作成されます。

→ その後、そのZIPをもとに``Backup_YYmmdd.iso``がこれまたデスクトップ上に作成されます。

→ 完了！ あとは、煮るなり、ImgBurnで物理ディスクに焼くなり、してください。

## 考慮したこと・ハマったところ

### 進捗バーの各処理ごとの割り当て問題。

ISO作成のProgressをとることが難しいため、ZIP作成までを1ステップとし、99％まで占有させた。残りの1％はISO作成に割り当てた。

### ``CancellationToken`` の実装時の機能的な問題点解決。

チェック頻度を分割しないと、ZIP作成完了までキャンセルトークンのチェックが回ってこず、GUI上のボタンを押してもキャンセル処理ができない。

そのため、細かなキャンセルトークンの発行を監視する目的で、ZIP作成を8KBおきのループに分割し、そのループの都度チェックを回す。

### (地味に)ISOファイルのファイル名とラベル名が別物ということに気づかずに小一時間ハマった

独立したメソッド(``GetSaveZipPath``などコメントアウトしたものを含む)でファイル名を作って代入、のフローを考えていたが、

ラベル名に拡張子は不要なので、代入時にいちいちその部分を除去する必要があるので本末転倒感があった。

そのため、メソッドの乱立を防ぐために、ラベル名の指定は``DateTime.Now:yyyyMMdd``として直接代入するアプローチに落ち着いた。

### 完了時のデスクトップ通知。

Windows11標準の通知センターを活用。

### partialクラスによるソースファイル分離。画面とロジックで分けてみた

当初``MainWindow.xaml.cs``のみに記述し、スクロールが多くなり可読性が大幅に低下していた。

そのため、保存名生成メソッド、ZIP作成メソッド、ISO作成メソッドを``MainWindow.xaml.Core.cs``として分離。

``partial``メソッドを用いて同一クラスを分割することで、保守性を保つプラクティスを体験できた。
